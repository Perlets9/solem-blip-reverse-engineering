## 1. Station-program-duration mapping — DECODED

The mapping "station N is on program P with duration D" lives in
**row 02 of each program**, sent via the write `37 11 02 [SLOT] [16 bytes]`.

### Row 02 layout (16 bytes)

```
[STN1_DUR:3] [STN2_DUR:3] [STN3_DUR:3] [STN4_DUR:3] [STN5_DUR:3] [PAD:1]
```

Each `STNk_DUR` is a 3-byte field:

```
byte 0: reserved / flag    (always 0x00 in observed data)
byte 1: duration_hi  ┐ BE16 duration in seconds, OR `0x0000` if this
byte 2: duration_lo  ┘ station is NOT assigned to this program
```

Followed by 1 trailing padding byte at position 15.

The row encodes up to **5 stations** in 16 bytes. BL1IP (1 station) and
BL2IP (2 stations) trivially fit; BL4IP (4 stations) still fits; **BL6IP
(6 stations) would not fit in this row alone** — it likely spills into the
next row (`37 11 03 [SLOT]`), which is always zero in the captures we
have. To be confirmed by a BL6IP capture.

### Evidence (run 3 writes)

**Program A** (slot `0x10`) — station 2 assigned, duration 77min = `0x120c`:

```
37 11 02 10 00 00 00 | 00 12 0c | 00 00 00 | 00 00 00 | 00 00 00 | 00
                      ^^^^^^^^^^
                      Station 2 → 0x120c = 4620s = 77min
```

Read as 5×3 byte stations + 1 pad:
- Station 1: `00 00 00` → not assigned to Program A ✓ (it's in C)
- Station 2: `00 12 0c` → 4620s = 1h17min ✓ (matches MySolem screenshot)
- Stations 3–5: `00 00 00` → unassigned (BL2IP has no stations 3–5)

**Program B** (slot `0x11`) — no stations:

```
37 11 02 11 00 00 00 | 00 00 00 | 00 00 00 | 00 00 00 | 00 00 00 | 00
```

All-zero → no station assigned to Program B ✓

**Program C** (slot `0x12`) — station 1 assigned, duration 27min = `0x0654`:

```
37 11 02 12 00 06 54 | 00 00 00 | 00 00 00 | 00 00 00 | 00 00 00 | 00
            ^^^^^^^^^^
            Station 1 → 0x0654 = 1620s = 27min
```

- Station 1: `00 06 54` → 1620s = 27min ✓
- Station 2: `00 00 00` → not assigned to Program C ✓ (it's in A)

Both screenshots match exactly. **High confidence**: this is the
station-to-program assignment + per-station-per-program duration storage.

## 2. Updated program record structure

Each program slot stores **7 rows** sent via opcodes `0x2f` (name) and `0x37`
(data). For Program A (slot `0x10`):

| Row | Opcode | Length | Decoded payload |
|---|---|---|---|
| `name`     | `2f 12 00 10` | 16 | ASCII name `"Program A"` (null-padded) |
| `unknown1` | `2f 12 01 10` | 16 | All zeros — reserved |
| `flags`    | `37 0e 00 10` | 14 | `00 00 00 [BUDGET] 00 [DAYS] [FREQ_FLAGS:2] [DD] [MM] [YY:BE16]` |
| `starts`   | `37 12 01 10` | 16 | 8× BE16 minutes-of-day, `0x05a0` sentinel for unused |
| `stations` | `37 11 02 10` | 16 | 5× 3-byte station entries (see §1) + 1 pad |
| `unknown3` | `37 11 03 10` | 16 | All zeros — reserved (possibly stations 6+ on BL6IP?) |
| `tail`     | `37 08 04 10` | 7  | All zeros — reserved |

`FREQ_FLAGS:2`: bytes 6–7 of the flags row. Observed values:
- Program A, B (active programs): `00 00`
- Program C (active in run 3): `02 00`
- All empty slots (4..12): `02 00`

So `02 00` is **not** "this program has stations" because empty slots have
it too. **Hypothesis**: `02 00` is the firmware default for fresh / never
edited programs; `00 00` appears after MySolem has written the program at
least once. Plausible but not conclusive — needs a capture where the user
changes the frequency from "Daily" to "every 2 days" to lock down what
this field really encodes.

## 3. Confirmed opcode summary

| Bytes | Direction | Purpose | Status |
|---|---|---|---|
| `31 05 12 [STN] 00 [SEC:BE16] + 3b 00` | write | Start station | ✅ |
| `31 05 11 00 00 [SEC:BE16] + 3b 00` | write | Start all stations | ✅ |
| `31 05 14 00 0N 00 00 + 3b 00` | write | Run program N (1..3), N at byte 4 BE16 | ✅ |
| `31 05 15 00 ff 00 00 + 3b 00` | write | Stop | ✅ |
| `3b 00` | write | Status (3-packet response) | ✅ |
| `0f 00 / e3 00 / f7 00` | write | Device info / serial / flags | ✅ |
| `41 00 / 3f ...` | read/write | Monthly water budget | ✅ |
| `39 00 / 2f.. / 37..` | read/write | Programs (name, flags, starts, **stations+durations**, tail) | ✅ |
| `35 00` | read | Returns 24 zero frames, **purpose still unknown** | ❓ |
| `03 06 00 ...` | write | Set timestamp | ✅ |

## 4. Remaining open questions (post run 3)

- **`FREQ_FLAGS` (`02 00` vs `00 00`)**: see §2.
- **Active-days bitmap bit ordering**: still need capture with a single day
  enabled.
- **Battery byte**: still need long-term sampling.

- **Station-rename opcode**: not yet observed.
